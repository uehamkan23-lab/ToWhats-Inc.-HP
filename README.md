# 常奥 ToWhats — 公式サイト

仙台高専の有志団体「常奥（とわつ / ToWhats）」のサイトです。

常陸・陸奥から笑顔を届ける。

HTML / CSS / JavaScript のみで作った静的サイトです。ビルド不要、依存パッケージなし。
`index.html` をブラウザで開けばそのまま動きます。

---

## デザインコンセプト：ステッカーのコラージュ × ポップ

- **トップ** — 赤い面に、メンバーの切り抜き写真を白いふち付きのステッカーのように散らしたコラージュ。手書きの英字ラベルと、画面の下を流れる大きな「TOWHATS」（参考：越前信用金庫 採用サイト）
- **遊び心** — 極太ゴシック、傾いたカード、ステッカー、触ると跳ねる動き
- **共通の決まり** — 太い藍色の枠線（3px）と、ずらした影。これで全要素をポップに揃えています

| 色 | 値 | 使いどころ |
|---|---|---|
| 藍 | `#1a2456` | 文字・枠線・影・夜空 |
| 朝日の黄 | `#ffc83d` | 太陽のステッカー・団体概要の背景 |
| 橙 | `#ff8f3f` | 朝焼け・メンバーの背景 |
| ロゴの赤 | `#d70009` | ステッカー・カード（ロゴと同じ赤） |
| トップの赤 | `#e0433a` | トップの背景（ロゴの赤を少し明るくした色） |
| 生成り | `#fff7e8` | ページの背景 |

## フォント（Morisawa Fonts）

| 役割 | 書体 | 選んだ理由 |
|---|---|---|
| 見出し | じゅん 501 | 丸ゴシックの極太。レトロポスター風の日の出と相性が良い |
| 本文 | A1ゴシック R / B | にじみのある柔らかいゴシック。手づくり感が出る |
| ステッカー | 那欽 | ポップな筆文字。遊び心の担当 |
| トップの英字ラベル | Caveat（Google Fonts） | 手書き風の英字。「Leader」「Let's play!」など |

### 表示させるための手順

Morisawa の Web フォントは、**Morisawa Fonts のアカウントに紐づいた埋め込みコード**がないと表示されません。

1. Morisawa Fonts の管理画面で、Web フォントを使うドメインを登録する
   （GitHub Pages なら `uehamkan23-lab.github.io`）
2. 上の3書体（じゅん 501 / A1ゴシック R・B / 那欽）を Web フォントとして有効にする
3. 発行された**埋め込みコード**を、`index.html` の `<!-- MORISAWA_EMBED_CODE -->` の位置に貼る
4. 管理画面に表示される **font-family 名**を、`style.css` 冒頭の `--display` / `--body` / `--body-bold` / `--hand` の先頭の名前（今は `"Jun 501"` などの仮の名前）と置き換える
5. 表示を確認できたら、`index.html` の Google Fonts の3行は削除してよい

Web フォントが使えるかどうかは、契約しているプランによって異なります。管理画面で確認してください。

埋め込みコードが入るまでは、代わりに Google Fonts の **Dela Gothic One** と **Zen Kaku Gothic New** で表示されます。

Morisawa の書体は太さごとに別の書体として配信されるため、`font-synthesis: none` を指定して、太字書体をさらに太く加工しないようにしています。

## ブログ・作品展示会の書き方（メンバー向け）

ブログと「ToWhats作品展示会」の作品は、同じ書く画面（`/blog/write/`）から公開します。どちらも **GitHub の書き込み権限を持っている人だけ** が公開できます。サイトにログインの仕組みを作る代わりに、GitHub の権限をそのまま使っています。

### 最初に1回だけ：アクセストークンを作る

1. リポジトリの持ち主（上原）が、ほかのメンバーを **Settings → Collaborators** で招待する
2. 各自の GitHub で **Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token**
3. **Repository access** で `ToWhats-Inc.-HP` だけを選ぶ
4. **Repository permissions → Contents** を **Read and write** にする
5. できたトークン（`github_pat_` で始まる）をどこかに控えておく

### 書いて公開する

1. `/blog/write/` を開き、トークンを貼って「接続する」
2. タイトル・書いた人・日付・URL に使う名前（例：`2026-09-27-start`）を入れる
3. 本文を書く。右側（スマホでは「プレビュー」タブ）に仕上がりが表示されます
4. 「画像を追加」で写真を入れられます。自動で横 1600px 以下に縮小されます
5. 「公開する」を押すと、1〜2分でサイトに反映されます

書き途中の文章は、その端末に自動で保存されます（画像は除く）。

### 作品展示会の作品を載せる

書く画面の上で「作品展示会の作品」を選ぶと、作品用の欄が出ます。

| 欄 | 内容 |
|---|---|
| 名前 | 作品名（例：NajoshiteAI） |
| 状態 | 制作中 / 公開中 / 完了 / 準備中 / なし。カードの左上に出ます |
| 時期 | 自由に書けます（例：2026年〜、令和7年度） |
| ひとことで | カードとページの先頭に出る短い説明 |
| 関わったメンバー | チェックした人の写真と名前がカードとページに出て、その人の紹介ページにも「関わっているもの」として載ります |
| メンバー以外で関わった人 | 学校の友達・協力してくれた団体など。文字でそのまま表示されます |
| サイトの URL | 作品のサイトや紹介記事 |
| URL に使う名前 | `/works/この名前/` になります（例：`najoshiteai`） |

関わった人は、メンバーか「メンバー以外」のどちらかに最低1人必要です。
一覧は、最後に更新した作品が先頭に来ます。

### お知らせ・実績を載せる

書く画面の上で「お知らせ・実績」を選ぶと、専用の欄が出ます。

| 欄 | 内容 |
|---|---|
| 種類 | お知らせ / 実績（受賞・出場・採択など）。色の違うラベルで表示されます |
| 日付・日付の表示 | 「年月日」「年月まで」「年だけ」から選べます。日にちが分からない実績は「年だけ」にしてください |
| タイトル | 一覧にそのまま出ます（例：〇〇コンテストで△△賞をいただきました） |
| 関わったメンバー | 任意。チェックした人の紹介ページにも「お知らせ・実績」として載ります |
| サイトの URL | 任意。主催者の発表ページや記事など |
| 本文 | 任意。詳しいことを書けます |

一覧は日付の新しい順です。今は、紹介ページに年が書かれている実績（SPARK!TOHOKU 2026・高校生ビジネスアイディアコンテスト2025）の2件だけを載せています。

### 直す・消す

「書く記事」「書く作品」「書くお知らせ・実績」から既存のものを選ぶと、読み込んで直せます。URL（名前）は後から変えられません。
削除は「削除する」を2回押します（元に戻せません）。

### 仕組み（開発する人向け）

- 公開すると、GitHub API で **1回のコミット** として次のファイルが保存されます。ブログは `blog/<名前>/index.html`・`post.md`・画像・`blog/posts.json`、ToWhats作品展示会は `works/<名前>/index.html`・`work.md`・画像・`works/works.json`、お知らせ・実績は `news/<名前>/index.html`・`news.md`・画像・`news/news.json`。どの場合も `sitemap.xml` を作り直して一緒に保存します
- 保存先のリポジトリとブランチ、公開先の URL（`siteUrl`）は `blog/config.js` にあります。公開するブランチを変えた（例：`main` にした）ときは、ここも変えてください
- ページのデザインを変えたいときは `blog/post-template.html`（記事）・`works/work-template.html`（作品）・`news/news-template.html`（お知らせ・実績）を編集します。すでに公開したページには反映されないので、その場合は書く画面で開いて「公開する」を押し直してください
- トークンは GitHub 以外には送られません。「この端末に保存する」にチェックしたときだけ、その端末のブラウザに残ります

## 動き

- **オープニング画面**：初めて開いたとき、ロゴの赤いマークが落ちてきて2回噛むように動き、「常」「奥」が飛び出したあと、幕が上がるように消える（1タブにつき1回。タップで飛ばせる。詳細は `assets/README.md`）
- オープニングの幕が上がると同時に、ステッカーが1枚ずつ弾むように貼られ、4人が下からせり上がり、手書きラベルの矢印が描かれていく
- ステッカーはゆっくり揺れ続け、スクロールするとそれぞれ違う速さで上に流れる（奥行きが出る）
- 画面下の「TOWHATS」は横に流れ続ける
- 各セクションは、画面に入ると下からバネのように現れる
- カード・写真・ボタンは、マウスを乗せると傾きが戻ったり跳ねたりする

`prefers-reduced-motion: reduce`（動きを減らす設定）の環境では、すべての動きを止めます。JavaScript が無効でも全文が読めます。

## サイトの見方

### 自分のパソコンで見る

1. GitHub のリポジトリページで **Code** → **Download ZIP**
2. 展開したフォルダの `index.html` をダブルクリック

### インターネットに公開する（GitHub Pages・無料）

このリポジトリは公開（public）なので、無料で公開できます。

1. GitHub のリポジトリ → **Settings** → 左メニューの **Pages**
2. **Source** を **Deploy from a branch** にする
3. **Branch** で `claude/portfolio-site-creation-3m6ltu`、フォルダは `/ (root)` を選んで **Save**
4. 1〜2分後、次の URL で見られるようになる

```
https://uehamkan23-lab.github.io/ToWhats-Inc.-HP/
```

以降は、このブランチに変更をプッシュするたびに自動で更新されます。

### 検索エンジンに登録する

- `sitemap.xml` にサイトのページがすべて載っています。記事・作品・お知らせを公開したり消したりすると、書く画面が自動で作り直します
- github.io の URL で公開している間は、`robots.txt` は検索エンジンに読まれません（ドメインの一番上に置いたものしか読まれないため）。[Google Search Console](https://search.google.com/search-console) にサイトを登録し、「サイトマップ」から `sitemap.xml` の URL を送ってください
- 独自のドメイン（例：`towhats.jp`）に移したら、`blog/config.js` の `siteUrl` と `robots.txt` の `Sitemap:` の URL を新しいドメインに書き換え、書く画面で何か1つ「公開する」を押し直すと `sitemap.xml` も新しい URL になります
- 書く画面（`/blog/write/`）と404ページは、検索結果に出ないように設定しています

### 404 ページ

存在しない URL を開くと、GitHub Pages が `404.html` を表示します。どの深さの URL でもリンクや画像が正しく読み込まれるよう、ページの最初で基準の場所（github.io では `/ToWhats-Inc.-HP/`、独自のドメインでは `/`）を決めています。手元で `index.html` を直接開いたときは確認できないので、公開してから `…/ToWhats-Inc.-HP/abc/` のような URL で試してください。
Vercel や Netlify でもビルド設定は不要です（フレームワークなし、出力ディレクトリはルート）。
