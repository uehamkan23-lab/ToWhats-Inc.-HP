# トワツ（ToWhats） — 公式サイト

仙台高専の学生団体「トワツ（ToWhats）」のサイトです。

答えは探求心の中にある。その探求心の着火剤を創る。

HTML / CSS / JavaScript のみで作った静的サイトです。ビルド不要、依存パッケージなし。
`index.html` をブラウザで開けばそのまま動きます。

---

## デザインコンセプト：企業サイトのつくりで、ゼロから組み直したもの

企業サイトの定番の構成（大きな写真のトップ・事業内容・会社概要・お問い合わせ）にならって、
「ひと目で、どんな団体で、何をしていて、どう連絡すればいいか」がわかる構成にしています。

- **地と色** — 地は白と、青みの薄いグレーを交互に。文字は濃紺。色はロゴから取り、青を主色（ボタン・リンク）、赤を差し色（小さな点だけ）に
- **見出し** — 大きな英字（ABOUT US・BUSINESS など）の下に、日本語の名前を小さく添える
- **トップ** — 校門の前の3人の写真を画面いっぱいに敷き、左に目標の文とボタン。その下に最新のお知らせを1行
- **活動内容** — 写真と文を左右交互に
- **理念** — 濃紺の帯に、めざす社会（ビジョン）を大きく、その下に大事な三本柱を3列
- **お問い合わせ** — どのページも、フッターの上に青い帯を置く（お問い合わせページ自身は除く）
- **ボタン** — 角を少しだけ丸めた四角に、小さな矢印

### 「AIっぽさ」を避けるために決めていること

AIで作ったサイトによく出る型のうち、次のものは使っていません：
色付きの点の付いた小見出し、丸いボタンに丸で囲んだ矢印、
大きな白抜きの番号 01・02・03、背景に薄く敷いた巨大な英字、カードが浮き上がるホバー、トップの文字が順番に出る動き。
文章も「〜を、〜する。」のような決め台詞を減らし、ふつうの言葉で書いています。

英字の大見出しと、スクロールで段落がふわっと出る動きは、相談のうえ残しています。
トップの写真の動き（左から現れて寄りから引き、そのあとゆっくり動き続ける）と、縦書きの「SCROLL」と下へ流れる細い光の線も、相談のうえ入れています。

### 写真がまだない場所（□の枠）

写真が必要な場所には、グレーの□の枠に「写真のお願い」として、どんな写真が必要かを書いています。
写真が用意できたら、`<figure class="ph" …>…</figure>` をまるごと `<img src="…" alt="…">` に置き換えてください。

トップのいちばん上と、私たち（/about/）のいちばん上は、校門の前の3人の写真（`assets/photos/team-gate.webp`、横長に切った `team-gate-wide.webp`）に差し替え済みです。活動内容 03 は、ミルクラフトのロゴ（`works/milcraft/logo.webp`）です。ミルクラフトは m3lab のプロジェクトで、トワツからは上原だけが参加しているので、載せる場所ではそのことを書いています。トップの「私たちについて」は会議の写真（`assets/photos/meeting.webp`。小さい元写真を3倍に拡大してシャープにし、紺と青の2色に加工）、トップのいちばん上の左側の背景は仙台の街並みと山（`assets/photos/sendai-skyline.webp`）です。トワツとは？の写真は活動している建物の外観（`assets/photos/base.webp`。傾きを直し、縦長に切って色を整えたもの）、理念の帯の背景は丘から見た街並み（`assets/photos/town-view.webp`）です。活動内容 02 は、AI甲子園での発表の写真（`works/wasufinder/cover.webp`。WasuFinder の作品カードと作品ページにも使用）に差し替え済みです。

## ブログ・作品展示会の書き方（メンバー向け）

ブログと「トワツ作品展示会」の作品は、同じ書く画面（`/blog/write/`）から公開します。どちらも **GitHub の書き込み権限を持っている人だけ** が公開できます。サイトにログインの仕組みを作る代わりに、GitHub の権限をそのまま使っています。

### 最初に1回だけ：アクセストークンを作る

1. リポジトリの持ち主（上原）が、ほかのメンバーを **Settings → Collaborators** で招待する
2. 各自の GitHub で **Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token**
3. **Repository access** で `ToWhats-Inc.-HP` だけを選ぶ
4. **Repository permissions → Contents** を **Read and write** にする
5. できたトークン（`github_pat_` で始まる）をどこかに控えておく

### 書いて公開する

1. `/blog/write/` を開き、トークンを貼って「接続する」
2. タイトル・書いた人・日付・URL に使う名前（例：`2026-09-27-start`）を入れる
3. 本文を書く。右側（スマホでは「プレビュー」タブ）に仕上がりが表示されます
4. 「画像を追加」で写真を入れられます。自動で横 1600px 以下に縮小されます
5. 「公開する」を押すと、1〜2分でサイトに反映されます

書き途中の文章は、その端末に自動で保存されます（画像は除く）。

### 作品展示会の作品を載せる

書く画面の上で「作品展示会の作品」を選ぶと、作品用の欄が出ます。

| 欄 | 内容 |
|---|---|
| 名前 | 作品名（例：NajoshiteAI） |
| 状態 | 制作中 / 公開中 / 完了 / 準備中 / なし。カードの左上に出ます |
| 時期 | 自由に書けます（例：2026年〜、令和7年度） |
| ひとことで | カードとページの先頭に出る短い説明 |
| 関わったメンバー | チェックした人の写真と名前がカードとページに出て、その人の紹介ページにも「関わっているもの」として載ります |
| メンバー以外で関わった人 | 学校の友達・協力してくれた団体など。文字でそのまま表示されます |
| サイトの URL | 作品のサイトや紹介記事 |
| URL に使う名前 | `/works/この名前/` になります（例：`najoshiteai`） |

関わった人は、メンバーか「メンバー以外」のどちらかに最低1人必要です。
一覧は、最後に更新した作品が先頭に来ます。

### お知らせ・実績を載せる

書く画面の上で「お知らせ・実績」を選ぶと、専用の欄が出ます。

| 欄 | 内容 |
|---|---|
| 種類 | お知らせ / 実績（受賞・出場・採択など）。色の違うラベルで表示されます |
| 日付・日付の表示 | 「年月日」「年月まで」「年だけ」から選べます。日にちが分からない実績は「年だけ」にしてください |
| タイトル | 一覧にそのまま出ます（例：〇〇コンテストで△△賞をいただきました） |
| 関わったメンバー | 任意。チェックした人の紹介ページにも「お知らせ・実績」として載ります |
| サイトの URL | 任意。主催者の発表ページや記事など |
| 本文 | 任意。詳しいことを書けます |

一覧は日付の新しい順です。今は、紹介ページに年が書かれている実績（SPARK!TOHOKU 2026・高校生ビジネスアイディアコンテスト2025）の2件だけを載せています。

### 直す・消す

「書く記事」「書く作品」「書くお知らせ・実績」から既存のものを選ぶと、読み込んで直せます。URL（名前）は後から変えられません。
削除は「削除する」を2回押します（元に戻せません）。

### 仕組み（開発する人向け）

- 公開すると、GitHub API で **1回のコミット** として次のファイルが保存されます。ブログは `blog/<名前>/index.html`・`post.md`・画像・`blog/posts.json`、トワツ作品展示会は `works/<名前>/index.html`・`work.md`・画像・`works/works.json`、お知らせ・実績は `news/<名前>/index.html`・`news.md`・画像・`news/news.json`。どの場合も `sitemap.xml` を作り直して一緒に保存します
- 保存先のリポジトリとブランチ、公開先の URL（`siteUrl`）は `blog/config.js` にあります。公開するブランチを変えた（例：`main` にした）ときは、ここも変えてください
- ページのデザインを変えたいときは `blog/post-template.html`（記事）・`works/work-template.html`（作品）・`news/news-template.html`（お知らせ・実績）を編集します。すでに公開したページには反映されないので、その場合は書く画面で開いて「公開する」を押し直してください
- トークンは GitHub 以外には送られません。「この端末に保存する」にチェックしたときだけ、その端末のブラウザに残ります

## 動き

- 各セクションは、画面に入ると下から静かに浮かび上がる
- トップの作品カードは、左から右へゆっくり流れ続ける。カーソルを乗せると止まる
- カードやボタンは、マウスを乗せると影が少し濃くなる

`prefers-reduced-motion: reduce`（動きを減らす設定）の環境では、すべての動きを止めます。JavaScript が無効でも全文が読めます。

## サイトの見方

### 自分のパソコンで見る

1. GitHub のリポジトリページで **Code** → **Download ZIP**
2. 展開したフォルダの `index.html` をダブルクリック

### インターネットに公開する（GitHub Pages・無料）

このリポジトリは公開（public）なので、無料で公開できます。

1. GitHub のリポジトリ → **Settings** → 左メニューの **Pages**
2. **Source** を **Deploy from a branch** にする
3. **Branch** で `claude/portfolio-site-creation-3m6ltu`、フォルダは `/ (root)` を選んで **Save**
4. 1〜2分後、次の URL で見られるようになる

```
https://uehamkan23-lab.github.io/ToWhats-Inc.-HP/
```

以降は、このブランチに変更をプッシュするたびに自動で更新されます。

### 検索エンジンに登録する

- `sitemap.xml` にサイトのページがすべて載っています。記事・作品・お知らせを公開したり消したりすると、書く画面が自動で作り直します
- サイトは `https://towhats.com/` で公開しています。`blog/config.js` の `siteUrl`、`robots.txt` の `Sitemap:`、`sitemap.xml` は、どれもこの URL です
- ドメインを変えたら、`blog/config.js` の `siteUrl` と `robots.txt` の `Sitemap:` の URL を新しいドメインに書き換え、書く画面で何か1つ「公開する」を押し直すと `sitemap.xml` も新しい URL になります

### Google の検索結果に出る内容

| 検索結果の場所 | どこで決まるか |
|---|---|
| サイト名（いちばん上の小さい文字） | `index.html` の `<script type="application/ld+json">` の `"name": "トワツ"` |
| アイコン | ルートの `favicon.ico` と `assets/favicon-96.png`・`assets/favicon.png`（白い丸にトワツのマーク） |
| タイトル（青や紫の大きい文字） | `index.html` の `<title>` |
| 説明文 | `index.html` の `<meta name="description">` |

書き換えても、Google の検索結果にはすぐには反映されません（数日〜数週間）。早めたいときは、[Google Search Console](https://search.google.com/search-console) の「URL 検査」で `https://towhats.com/` を調べ、「インデックス登録をリクエスト」を押してください。
- 書く画面（`/blog/write/`）と404ページは、検索結果に出ないように設定しています

### CSS・JS を変えたとき（表示が崩れて見えるときも）

ページから読み込む CSS と JS には、`style.css?v=20261110b` のように版の番号を付けています。
ブラウザが古い CSS を覚えたまま新しいページを表示して、見た目が崩れるのを防ぐためです。
`style.css` や `script.js` などを書き換えたら、エディタの「すべてのファイルで置換」で
`?v=20261110b` を新しい番号（例：`?v=20261201a`）に置き換えてください。

### 404 ページ

存在しない URL を開くと、GitHub Pages が `404.html` を表示します。どの深さの URL でもリンクや画像が正しく読み込まれるよう、ページの最初で基準の場所（github.io では `/ToWhats-Inc.-HP/`、独自のドメインでは `/`）を決めています。手元で `index.html` を直接開いたときは確認できないので、公開してから `…/ToWhats-Inc.-HP/abc/` のような URL で試してください。
Vercel や Netlify でもビルド設定は不要です（フレームワークなし、出力ディレクトリはルート）。
